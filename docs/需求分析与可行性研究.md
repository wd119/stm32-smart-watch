## 摘要

本项目以 STM32F103C8T6 为主控，设计并实现一款多功能可编程手表。系统以 0.96 寸 OLED 为显示终端，以三按键为唯一输入通道，集成了实时时钟、时间设置、秒表、手电筒、姿态显示、水平仪、小恐龙游戏、表情动画、电池电量检测与长按关机共 12 项功能。软件采用 StdPeriph V3.5.0 标准外设库，按 `User` / `App` / `Bsp` 三层结构组织，自研代码合计 4531 行，划分为 9 个功能页面与 7 类板级驱动。

本文档对上述系统进行需求分析与可行性研究。需求分析部分给出 12 项功能需求与 5 类非功能需求，并逐条核对实现状态；可行性研究部分从技术、经济、操作、法律四个维度论证项目可行性，并对已识别的 7 项缺陷与 5 项风险给出评估。结论：项目在技术上已由实机验证可行，资源余量充足（Flash 占用 57.8%，SRAM 占用 15.1%），主要风险集中在电源与时钟的硬件依赖及部分无超时的阻塞式等待，均可通过有限改动消除。

**关键词**：STM32F103；可编程手表；需求分析；可行性研究；嵌入式系统

## 1 引言

### 1.1 编写目的

本文档的编写目的有三：

1. **固化需求基线**。项目在实现过程中功能不断叠加，但从未形成书面需求。这导致"哪些是需求、哪些是顺手加的"边界模糊，新增功能时缺少判断依据。
2. **论证继续开发的可行性**。项目已完成第一阶段功能实现，后续需要决定是继续扩展功能、还是转向质量加固。本文档为这一决策提供依据。
3. **作为后续开发与验收的基准**。文档中编号化的需求条目（FR-xx / NFR-xx）可直接用于任务拆分、提交信息引用与最终验收。

预期读者为：项目开发者本人、课程指导教师、以及任何需要接手该代码的后续开发者。

### 1.2 项目背景

本项目源于一套 STM32 教学课程，课程以"每课增加一个功能"的方式逐步搭建一个可编程手表。当前工程对应课程第 1 至第 10 课，已完成电源模块与长按关机功能，目录名为 `1-10电源模块和长按关机`。

教学式累进开发的特点是"功能可达、结构未治"。到第 10 课为止，工程已经出现了目录结构未分层、中断服务函数散落在入口文件、同一段页面骨架被复制十余次、源码编码与换行符混用等问题。本项目在这一节点上转向工程化整理，本文档是这一转向的起点。

## 2 项目概述

### 2.1 系统定位

本系统是一款**单机、离线、低功耗、三按键**的手持式多功能数字手表。系统不包含任何无线通信、外部存储扩展或上位机交互，全部功能在板内闭环完成。

交互模型极为简单：一块 128×64 单色屏幕负责全部输出，三个物理按键负责全部输入。这一模型决定了需求分析中的所有交互约束——**任何功能必须在两层页面以内可达，任何页面必须以第三次按键（K3）返回**。

### 2.2 硬件平台

| 项目 | 规格 |
| :--- | :--- |
| 主控 | STM32F103C8T6，ARM Cortex-M3，最高 72 MHz |
| Flash | 64 KB |
| SRAM | 20 KB |
| 显示 | 0.96 寸 OLED，128×64 单色，SSD1306 驱动，I2C 接口 |
| 姿态传感器 | MPU6050，三轴加速度计 + 三轴陀螺仪，I2C 接口 |
| 实时时钟 | 内置 RTC，LSE 32.768 kHz 晶振，VBAT 后备供电 |
| 输入 | 三按键（K1 / K2 / K3），K3 支持长按识别 |
| 输出 | 手电筒白光 LED、OLED |
| 电源 | 锂电池供电，板载分压后接 ADC 采样 |

### 2.3 软件平台与工具链

| 项目 | 规格 |
| :--- | :--- |
| 器件宏 | `STM32F10X_MD`（中容量），`USE_STDPERIPH_DRIVER` |
| 外设库 | ST StdPeriph Library V3.5.0 |
| IDE | Keil MDK（µVision） |
| 编译器 | ARMCC |

### 2.4 现有软件结构

工程按三层组织，依赖方向严格自上而下：

```
User/    入口与中断向量    main.c、stm32f10x_it.c
  ↓
App/     业务逻辑          9 个功能页面、菜单框架、游戏、时间设置
  ↓
Bsp/     板级驱动          OLED、MPU6050、RTC、ADC、按键、LED、延时、定时器
```

各层规模实测如下：

| 层 | 文件数 | 行数 | 职责 |
| :--- | ---: | ---: | :--- |
| `User/` | 4 | 335 | 系统入口、中断服务、库配置 |
| `App/` | 12 | 1005 | 功能页面与业务流程 |
| `Bsp/` | 38 | 3191 | 硬件驱动（其中 OLED.c + OLED_Data.c 占 2528 行） |
| **自研合计** | **54** | **4531** | |
| `Library/` | 46 | — | ST 标准外设库，第三方 |
| `Start/` | 13 | — | 启动文件与 CMSIS，第三方 |

`Bsp/` 层中 `OLED.c`（1488 行）与 `OLED_Data.c`（1040 行）为字库与显存实现，合计占该层 79%。剔除后板级驱动的实际逻辑量约 663 行，与 `App/` 层同量级。

## 3 需求分析

### 3.1 功能需求

功能需求编号规则为 `FR-序号`，优先级分为三级：**必须**（核心功能，缺失则产品不成立）、**应当**（重要但可延后）、**可选**（增强项）。

| 编号 | 功能名称 | 需求描述 | 优先级 | 实现状态 |
| :--- | :--- | :--- | :--- | :--- |
| FR-01 | 时钟显示 | 在首页显示年-月-日与时:分:秒，秒级刷新，走时断电不丢 | 必须 | 已实现 |
| FR-02 | 时间设置 | 可逐项调整年、月、日、时、分、秒六个字段，改动即时写入 RTC | 必须 | 已实现 |
| FR-03 | 主菜单导航 | 以横向滚动列表呈现功能入口，带平滑位移动画 | 必须 | 已实现 |
| FR-04 | 秒表 | 计时精度 1 秒，支持开始、停止、清零三种操作 | 应当 | 已实现 |
| FR-05 | 手电筒 | 通过白光 LED 提供照明，可开关 | 应当 | 已实现 |
| FR-06 | 姿态显示 | 实时显示 Roll / Pitch / Yaw 三轴角度 | 可选 | 已实现 |
| FR-07 | 水平仪 | 以圆形气泡方式直观指示水平状态 | 可选 | 已实现 |
| FR-08 | 小恐龙游戏 | 跳跃躲避障碍物的横版跑酷小游戏，含计分 | 可选 | 已实现 |
| FR-09 | 表情动画 | 播放眨眼表情动画 | 可选 | 已实现 |
| FR-10 | 电池电量显示 | 在时钟页显示剩余电量百分比与图形化电池图标 | 应当 | 已实现（数值待校准） |
| FR-11 | 长按关机 | 长按 K3 约 1 秒触发关机 | 必须 | 已实现（仅首页有效） |
| FR-12 | 快捷开关机 | 首页 K3 提供独立的关机按键项 | 必须 | 已实现 |

**FR-01 时钟显示**的补充约束：初始时间硬编码于 `MyRTC.c` 的 `MyRTC_Time[] = {2026,9,7,18,15,0}`，仅在首次上电（BKP_DR1 非 `0xA5A5`）时写入。此后依赖 VBAT 维持 RTC 走时，重新上电不再重置。

**FR-11 长按关机**的补充约束：长按识别在 `key.c` 的 `Key_GetState()` 中实现，`press_time > 1000`（1 ms 时基下约 1 秒）返回键值 4。但当前**仅 `First_Page_Clock()` 处理了键值 4**，在菜单及其余功能页中长按会被忽略。这构成一项已知的交互不一致，见 3.3 节缺陷 D-6。

### 3.2 非功能需求

#### NFR-1 性能需求

| 编号 | 指标 | 要求 | 实测/推算 |
| :--- | :--- | :--- | :--- |
| NFR-1.1 | 按键响应延迟 | ≤ 50 ms | 20 ms 采样周期，含消抖理论最坏 40 ms，**满足** |
| NFR-1.2 | 时钟走时精度 | 日误差 ≤ 2 s | 依赖 LSE 晶振，未做长时实测，**待测** |
| NFR-1.3 | 姿态刷新率 | ≥ 50 Hz | 受 `Delay_ms(5)` 限制，理论上限 200 Hz，实际更低，**满足** |
| NFR-1.4 | 单帧 UI 阻塞时长 | ≤ 30 ms | 电池采样一次阻塞约 17 ms，**边界达标但无余量** |

NFR-1.4 的推算依据：ADC 时钟配置为 PCLK2/6，即 72 MHz ÷ 6 = 12 MHz。单次转换耗时 =（采样 55.5 周期 + 转换 12.5 周期）÷ 12 MHz = 5.67 µs。`Show_Batterry()` 每次执行 3000 次单次转换求平均，纯转换时间约 **17 ms**。该函数由 `Show_Clock_UI()` 调用，而 `Show_Clock_UI()` 位于主循环每一轮中，即**时钟页每帧都要阻塞约 17 ms**。详见缺陷 D-2。

#### NFR-2 可靠性需求

| 编号 | 指标 | 要求 | 现状 |
| :--- | :--- | :--- | :--- |
| NFR-2.1 | 时基稳定性 | 提供 1 ms 精确定时基准 | TIM2 实现，抢占优先级 2 / 子优先级 1 |
| NFR-2.2 | 按键抖动抑制 | 消除机械抖动误触发 | 20 ms 周期采样 + 释放沿判键 |
| NFR-2.3 | 掉电走时 | 主电源断开后时钟继续 | 依赖 VBAT + LSE，硬件条件具备 |
| NFR-2.4 | 死锁防护 | 任何阻塞等待均应有超时 | **不满足**，存在 2 处无超时死等 |
| NFR-2.5 | 异常自恢复 | 程序跑飞后可自动复位 | **不满足**，未启用 IWDG |

NFR-2.4 指出的两处无超时死等：

- `Bsp/AD.c:36` — `while(ADC_GetFlagStatus(ADC1, ADC_FLAG_EOC) == RESET);`：若 ADC 未启动或时钟异常，程序永久停在此处。
- `Bsp/MyRTC.c:12` — `while(RCC_GetFlagStatus(RCC_FLAG_LSERDY) == RESET);`：若 32.768 kHz 晶振缺失或不起振，**程序会在初始化阶段永久卡死，屏幕全黑**，现象上表现为"整机不启动"。此条严重度高于前者。

#### NFR-3 可维护性需求

| 编号 | 指标 | 要求 | 现状 |
| :--- | :--- | :--- | :--- |
| NFR-3.1 | 分层清晰 | 依赖方向单向，不出现跨层反向调用 | 已满足，见 2.4 节 |
| NFR-3.2 | 中断归位 | 中断服务函数集中于中断向量文件 | 已满足 |
| NFR-3.3 | 消除重复 | 相同骨架不应重复出现 | **不满足**，见缺陷 D-5 |
| NFR-3.4 | 编码统一 | 全工程使用同一种源码编码 | **不满足**，GBK 与 UTF-8 混用 |
| NFR-3.5 | 换行统一 | 全工程使用同一种换行符 | **不满足**，LF 与 CRLF 混用 |
| NFR-3.6 | 零告警 | 编译无警告 | **不满足**，29 条警告（其中 28 条为文件末尾缺换行） |

#### NFR-4 资源占用需求

| 编号 | 指标 | 上限 | 实测 | 占用率 | 余量 |
| :--- | :--- | ---: | ---: | ---: | ---: |
| NFR-4.1 | Flash 占用 | 64 KB | 37.9 KB | **57.8 %** | 27.0 KB |
| NFR-4.2 | SRAM 占用 | 20 KB | 3.1 KB | **15.1 %** | 17.0 KB |

实测数据取自 `Listings/Project.map`：

```
Total RO  Size (Code + RO Data)                37704 (  36.82kB)
Total RW  Size (RW Data + ZI Data)              3096 (   3.02kB)
Total ROM Size (Code + RO Data + RW Data)      37872 (  36.98kB)
```

**结论：资源余量充足。** Flash 尚有 27 KB 可用，足以支撑后续功能扩展；SRAM 仅用 15.1%，无优化压力。这一结论直接支持 3.4 节的版本规划——系统有能力承载更多功能，瓶颈不在资源。

### 3.3 已知缺陷与待改进项

以下缺陷均经静态检查或构建日志证实，非推测。

| 编号 | 缺陷描述 | 位置 | 严重度 | 状态 |
| :--- | :--- | :--- | :--- | :--- |
| D-1 | 电池百分比端点硬编码为 `(ADValue-3276)*100/815`，缺乏两点校准流程，换板后数值失效 | `App/menu.c:27` | 中 | 未修复 |
| D-2 | 电池采样每帧阻塞 3000 次 ADC 转换（约 17 ms），无缓存机制 | `App/menu.c:19-24` | 中 | 未修复 |
| D-3 | 电池百分比缺少上限钳位，`Battery_Capacity > 100` 时显示异常 | `App/menu.c:28` | 低 | 未修复 |
| D-4 | ADC 转换完成标志采用无超时死等 | `Bsp/AD.c:36` | 中 | 未修复 |
| D-5 | LSE 起振采用无超时死等，晶振异常时整机卡死在初始化阶段 | `Bsp/MyRTC.c:12` | **高** | 未修复 |
| D-6 | 长按关机仅在时钟首页生效，菜单及功能页中长按被忽略 | `App/menu.c` 等多处 | 低 | 未修复 |
| D-7 | `StopWatch_Tick()` 隐式声明（`#223-D`），C90 下按 `int` 处理，属未定义行为 | `User/stm32f10x_it.c:162` | 中 | **已修复** |

**D-7 的说明**：该缺陷源于一次目录重构——函数从 `menu.c` 迁至 `app_stopwatch.c`，声明随之从 `menu.h` 迁至 `app_stopwatch.h`，但中断文件中的 `#include "menu.h"` 未同步修改。因 C90 允许隐式声明，编译器按 `int StopWatch_Tick()` 处理，而实际函数无参数、返回 `void`，在 ARM 调用约定下恰好行为正确，故功能实测正常。但一旦函数签名变更或编译器切换至 C99 模式，将立即变为硬错误。已在提交 `44d321a` 中修正为包含 `app_stopwatch.h`。

### 3.4 需求优先级与版本规划

综合 3.1 节实现状态与 3.3 节缺陷清单，后续工作按以下优先级推进：

| 阶段 | 内容 | 依据 |
| :--- | :--- | :--- |
| 一 | 修复 D-5、D-4（消除无超时死等） | 唯一可能导致整机不可用的缺陷 |
| 二 | 修复 D-1、D-2、D-3（电池链路） | 当前显示数值不可信，且每帧阻塞 |
| 三 | 修复 D-6，统一长按语义 | 交互一致性 |
| 四 | 消除代码重复（NFR-3.3） | 可维护性，为后续扩展铺路 |
| 五 | 统一编码与换行符（NFR-3.4、NFR-3.5） | 工程卫生，不改逻辑 |
| 六 | 启用 IWDG（NFR-2.5） | 异常自恢复 |

## 4 可行性研究

### 4.1 技术可行性

#### 4.1.1 结论

**技术上完全可行，且已由实机验证。** 本项目的特殊性在于：需求分析的对象已经是一个可以正常运行的成品，而非待建系统。因此技术可行性的论证不是"能否做到"，而是"现有实现是否已达要求、继续演进是否有余量"。

#### 4.1.2 主控能力核算

STM32F103C8T6 在 72 MHz 下约可提供 1.25 DMIPS/MHz × 72 = 90 DMIPS 的算力。本项目的主要计算负载为：

| 负载 | 频次 | 说明 |
| :--- | :--- | :--- |
| 互补滤波姿态解算 | 约 200 Hz | 含 2 次 `atan2()` 浮点三角函数 |
| OLED 全屏刷新 | 视页面而定 | 128×64 位 = 1024 字节，经软件 I2C 传输 |
| 电池采样 | 每帧 3000 次 | 见 NFR-1.4 |

Cortex-M3 **不带硬件浮点单元（FPU）**，所有 `float` / `double` 运算由软件浮点库模拟，单次 `atan2()` 开销可达数百周期。这是本系统最重的计算负载。实测系统在该负载下运行正常，说明主控能力满足要求。

#### 4.1.3 外设资源占用

| 外设 | 用途 | 占用引脚 |
| :--- | :--- | :--- |
| TIM2 | 1 ms 系统时基，驱动按键消抖与各功能计时 | 无（内部） |
| ADC1 | 电池电压采样，通道 0 | PA0 |
| RTC | 实时时钟，LSE 32.768 kHz | 晶振引脚 |
| BKP | 后备寄存器 DR1，标记 RTC 是否已初始化 | 无（内部） |
| GPIO | 按键、LED、软件 I2C、电源自锁 | PA4、PA6、PB1、PB10、PB11、PB12、PB13、PB15 |

**冲突提示**：PB12 在 `Bsp/Buzzer.c:8` 中被配置为蜂鸣器输出，同时在 `User/main.c:78` 中被用于电源自锁控制（关机时置高）。`Buzzer_Init()` 会重新初始化该引脚为普通推挽输出。当前 `Buzzer.c` 未被任何代码调用，故无实际影响；但**若后续接入蜂鸣器功能，必须先解决引脚复用冲突**，否则可能破坏关机电路。此条列为风险 R-3。

#### 4.1.4 存储与内存余量

由 NFR-4 实测数据，Flash 余量 27.0 KB、SRAM 余量 17.0 KB。即使再增加 3 至 4 个同规模功能页面，Flash 占用预计仍在 70% 以内。**资源不构成约束。**

#### 4.3.3 可操作性评估

操作可行性的主要用户即项目开发者本人，无外部用户培训成本。界面采用图形化图标而非纯文字，菜单以横向滚动动画呈现，直观性良好。

### 4.5 风险分析

| 编号 | 风险描述 | 可能性 | 影响 | 应对措施 |
| :--- | :--- | :--- | :--- | :--- |
| R-1 | LSE 晶振不起振导致整机卡死在初始化（对应 D-5） | 中 | **高**（整机不启动） | 为 LSE 起振等待增加超时计数，超时后降级使用 LSI 或跳过 RTC 初始化并在屏幕提示 |
| R-2 | 电池电量读数不准确，用户无法判断剩余电量（对应 D-1、D-3） | 高 | 中 | 引入两点校准流程，修正分压比与参考电压，补充上限钳位 |
| R-3 | PB12 引脚被蜂鸣器与电源自锁复用，接入蜂鸣器可能破坏关机电路 | 低（当前未接入） | **高**（可能无法关机） | 接入蜂鸣器前先核对原理图，更换引脚或改用软件复用时序 |
| R-4 | 无看门狗，程序跑飞后无法自恢复（对应 NFR-2.5） | 中 | 中 | 启用 IWDG，在主循环与中断回调中喂狗 |
| R-5 | Keil 评估版 32 KB 代码限制与当前 36.82 KB 代码段冲突 | 待核实 | **高**（构建产物可能不完整） | 确认授权类型，或迁移至 GCC / CLANG 工具链 |

风险等级判定说明：**影响为"高"的 R-1、R-3、R-5 应优先处理**。其中 R-1 是唯一已具备触发条件且会导致整机失效的风险；R-3 当前处于潜伏状态；R-5 需先核实事实。

## 5 结论

**技术可行性：成立。** 系统已实机运行验证，12 项功能需求中 11 项完全实现、1 项（电池电量）实现但数值待校准。资源余量充足（Flash 57.8%、SRAM 15.1%），主控算力满足浮点姿态解算需求，不存在技术瓶颈。

**经济可行性：成立。** 硬件均为通用市售模块，无定制成本；软件全部使用免费或已有的工具链。唯一待核实项为 Keil 授权与 32 KB 代码限制的冲突（R-5）。

**操作可行性：成立。** 三按键 + 单屏的交互模型简单直观，页面深度不超过两层，用户不会迷路。长按语义不一致（D-6）是可感知的操作缺陷，但影响有限，可在后续迭代中修复。

**法律可行性：成立。** 自研代码无许可约束，第三方库均遵循可用许可，系统不含无线通信功能。作为课程设计用途无风险；若公开分发需补充确认第三方驱动的许可来源。

**总体结论：本项目可行，建议继续推进。** 后续工作不应优先扩展功能——资源虽有余量，但**当前主要矛盾是已有实现的质量**。建议严格按 3.4 节的优先级顺序推进：先消除可能导致整机失效的无超时死等（D-5、D-4），再修正电池链路（D-1、D-2、D-3），之后才是结构优化与工程卫生。功能扩展（如闹钟、计步）应排在质量项之后。
